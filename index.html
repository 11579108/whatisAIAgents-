AI Agents 是什麼？

給完全沒接觸過的人：5 分鐘看懂 AI Agent　·　資料來源：自建 LLM Wiki（5 篇 ingest）

1. 一句話定義

Agent ＝ 讓 LLM 拿著工具，在一個「有終點的迴圈」裡，一直做到目標完成。

平常的聊天 AI 是「你問、它答」一次結束。Agent 則是「想一步 → 用工具做一步 → 看結果 → 再想下一步」，直到達成目標或碰到停止條件。工具可以是搜尋、計算機、執行程式、查資料庫。WillisonAnthropic

2. 它由什麼組成？

大腦：LLM負責理解、推理、決定下一步。
手腳：工具 Tools搜尋、API、程式執行，讓 AI 能「真的做事」。
規則：指令與護欄告訴它該做什麼、不能做什麼。

另一種常見拆法（Lilian Weng）：規劃（把大事拆小事、反思修正）、記憶（短期＝對話內容，長期＝外部資料庫）、工具使用。兩種說法本質相同，只是切法不同。OpenAIWeng

3. Workflow 與 Agent 差在哪？

Workflow（工作流）Agent（代理）
誰決定步驟？程式事先寫好路徑LLM 邊做邊決定
優點可預測、穩定、好除錯彈性高，能處理沒料到的情況
代價遇到新狀況不會變通較慢、較貴、較難控制
適合步驟明確的任務步驟無法預先寫死的開放任務

建議：先從最簡單的做起，只有在確定能改善結果時才增加複雜度。多數情況下，一次 LLM 呼叫加上檢索就夠了。Anthropic

4. 邊想邊做：ReAct

ReAct 讓模型「推理」和「行動」交錯進行：先想要查什麼，查完再依結果調整下一步。論文中，模型透過維基百科 API 查證，減少了憑空捏造與錯誤累積；在 ALFWorld 與 WebShop 兩個互動任務上，成功率分別比模仿學習與強化學習基準高出 34% 與 10%（絕對值）。ReAct

生活比喻：你要煮晚餐 → 先想「可能有什麼食材」→ 打開冰箱看 → 發現沒蛋 → 改煮別的。這就是想與做交錯。

5. 為什麼需要護欄與檢查？

  • Agent 會自己動手，所以要限制它能做什麼（護欄），而且單一護欄不夠，要多層疊加。
  • 迴圈要有停止條件，否則會無止盡地跑。
  • 工具的說明寫得好不好，影響程度不亞於提示詞本身。

6. 小測驗

Q1：只問一次就回答的聊天機器人，算 Agent 嗎？通常不算：沒有用工具、沒有迴圈。
Q2：什麼任務適合用 Workflow 而不是 Agent？步驟固定、需要穩定可預測的任務。
Q3：為什麼迴圈要有停止條件？避免無限執行，也讓成本與風險可控。
